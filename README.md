# スス子文庫（Susuko Bunko）

自托管同步的轻小说 / 漫画阅读器。书、合集和阅读进度都放在你自己的服务器上，Windows、安卓和浏览器看到的是同一个书架。

<img width="897" height="662" alt="截图_2026-11-19_14-24-28" src="https://github.com/user-attachments/assets/0c850261-f19b-44d4-83e2-c635d84650c2" />

- **账号**：登录自己服务器上的账号，多端同步；不登录也能在本机完整使用，登录后可以把本机书库一键上传。可以换头像、改昵称、改密码
- **书架**：立体书架（默认，书本沿弧线摆开，可拖、甩、循环；书脊按文库排版——文库小标、竖排书名（自动缩放，保证完整显示）、卷号、作者、文库名，底色取封面主色；下方显示选中书的标题和简介）/ 封面 / 列表三种视图；自建合集、在读 / 已读完 / 未分类、搜索（书名、作者、画师、出版社）、多选整理；底部“继续阅读”浮条
- **主题色**：六种预设、自选颜色、从图片取色、跟随在读的书的封面；整套界面色调跟着变，深浅色各一套
- **图书详情**：封面、作者、插画、出版社 / 文库（内置 40 多个日本文库和中文出版社，可检索）、出版时间、系列卷号、简介（导入时从 EPUB 读取，可自己改）、评分、书评、阅读时长
- **系列与卷号**：导入时自动识别；同系列叠成一本，点开按卷号排列，顶部是系列介绍（可自己写，也可以让阅读助手按书名写一段）；也可以多选后“设为系列”批量编号
- **小说阅读**：横排左右翻页（逐段浮现 / 浮现 / 滑动动画，速度可调，书页跟手，宽屏双页；点屏幕两侧可设为都翻下一页；手机上翻页轻震；自动翻页；全书搜索）、上下滚动、竖排；字号、行距、页边距、段落间距、字体、配色；改排版时文字有过渡动画；目录、进度条；按住插画放大
- **划线与批注**：长按选字（按词 / 句 / 段，选中后可切换）→ 复制、划线（直线 / 波浪线 / 荧光笔，四种颜色）、批注、查词、翻译、问助手、从这里朗读；书签和整页笔记；“摘录与批注”页按书汇总，可回到原文
- **阅读助手**：接 OpenAI 兼容接口（OpenAI、DeepSeek、通义、Kimi、Ollama 等），查词、翻译（可设默认目标语言）、提问；提示词可以改；可经服务器转发
- **听书**：系统语音（免费）或接口语音；一句一句读并高亮，自动翻页、自动进下一章；可调语速，可定时停止（15 / 30 / 60 分钟或读完本章）
- **统计**：总时长和上一段的对比、连续阅读天数、每天 / 周 / 月柱状图、阅读日历、一天里的阅读节律、星期分布、每本书时长、最近划下的句子
- **漫画**：翻页（默认日漫右翻，宽屏双页）或下拉长条
- **同步**：书籍文件、进度、合集、书签批注、书评、阅读时长，以及设置（阅读助手接口、听书、排版、主题色等，换设备登录不用重新填）。没下载的书边读边加载；读过或手动下载的书存在本机，离线也能读
- **安卓**：音量键翻页、系统语音朗读（由原生层提供）

## 目录结构

```
app/         客户端界面（纯 HTML/CSS/JS，没有构建步骤）
server/      同步服务端（Node.js，零依赖，单文件）
src-tauri/   Windows / 安卓的原生外壳（Tauri 2）
```

三端共用 `app/` 这一份界面：服务端直接托管它（浏览器访问），Tauri 把它打包成原生应用。

## 1. 部署服务端（Ubuntu）

需要 Node.js 18 以上，不用 `npm install`。

```bash
sudo mkdir -p /opt/shiori && sudo cp -r app server /opt/shiori/
cd /opt/shiori
SHIORI_KEY=一串足够长的随机密钥 node server/server.js
```

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SHIORI_KEY` | 必填 | 邀请码，至少 8 位。注册账号时要填，防止别人在你的服务器上开账号 |
| `OPEN_SIGNUP` | 不设 | 设为 `1` 时注册不需要邀请码 |
| `PORT` | `8787` | 监听端口 |
| `HOST` | `127.0.0.1` | 只监听本机，对外由 nginx 转发 |
| `DATA_DIR` | `server/data` | 书、封面和 `db.json` 的存放位置，备份这个目录即可 |
| `MAX_BOOK_MB` | `2048` | 单本书的大小上限 |

长期运行用 `server/shiori.service`（systemd），对外访问用 `server/nginx.conf.example` 配 HTTPS 反向代理。**请务必走 HTTPS**：密码和登录凭证是随请求发送的，而且安卓默认不允许应用访问明文 HTTP。

部署好之后，用浏览器打开 `https://你的域名/` 就是网页版，填入密钥即可使用。

## 2. 打包客户端（推荐：让 GitHub 代劳）

不想在自己电脑上装 Rust 和 Android Studio 的话：把整个项目推到一个 GitHub 仓库（私有的也行），打开仓库的 **Actions → 打包客户端 → Run workflow**。跑完后在运行页面底部下载 `windows-installer`（安装包）和 `android-apk`。安卓签名的设置方法写在 `.github/workflows/build.yml` 开头。

下面两节是在自己电脑上打包的方法。

## 2a. 在本机打包 Windows 客户端

准备：[Rust](https://rustup.rs)、Node.js、Visual Studio C++ 生成工具（WebView2 在 Win10/11 上自带）。

```bash
npm install
npm run dev            # 开发调试
npm run build:windows  # 安装包在 src-tauri/target/release/bundle/nsis/
```

## 2b. 在本机打包安卓客户端

准备：Android Studio（SDK + NDK）、JDK 17，并按 [Tauri 的安卓环境说明](https://tauri.app/start/prerequisites/#android) 设置 `ANDROID_HOME`、`NDK_HOME`。

```bash
rustup target add aarch64-linux-android armv7-linux-androideabi
npm install
npx tauri icon src-tauri/app-icon.png   # 生成各尺寸图标（含安卓）
npx tauri android init
npm run build:android                    # APK 在 src-tauri/gen/android/app/build/outputs/apk/
```

正式安装需要给 APK 签名，见 Tauri 文档的 Android 签名一节。嫌麻烦的话，安卓上也可以直接用 Chrome 打开网页版，选“添加到主屏幕”。

## 2c. 构建苹果客户端

使用 Xcode 26 或更新版本构建。iPadOS、iOS 和 macOS 26 起，书架和阅读器工具栏使用系统液态玻璃。iPad 大窗口同时显示侧栏、书架和图书详情，窄窗口会把详情浮在书架上。

iPhone、iPad 和 Mac 共用 `src-tauri/icons/AppIcon.icon`。用 Icon Composer 编辑图层，Xcode 在构建时编译系统外观和旧系统所需的静态图标。Safari 添加到主屏幕时使用 `app/apple-touch-icon.png`。

```bash
npm install
npx tauri build --bundles app          # macOS
rustup target add aarch64-apple-ios
npx tauri ios build --no-sign          # 未签名 IPA
```

## 2d. 发布新版本

GitHub Actions 会自动打包四个平台。改好版本号（`package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`、`server/server.js`）并在下面“升级服务端”里写一行 `**版本号**：更新说明`，然后推一个标签：

```bash
git tag v0.13.2
git push origin v0.13.2
```

Windows、安卓、iOS、macOS 都打包成功后，会自动创建 GitHub Release，上传四个安装包，说明取自 README 里那一行。标签里带“-”（如 `v0.13.1-beta.1`）的标成预发布。只想试打包时，在 Actions → “打包客户端” → Run workflow，安装包在运行页面底部的 Artifacts 里，不会发布。

iOS 是未签名 IPA（用 AltStore、SideStore 等自签安装）；macOS 只有临时签名、没有公证，第一次打开要右键 → 打开。要上架或免提示安装，需要 Apple 开发者账号的证书。

## 百度网盘（放大体积的漫画）

漫画可以留在百度网盘里，书架上只记位置：看书时由你的服务器拿着授权去网盘取正在看的那几页转给客户端，不占服务器硬盘（但会走服务器的流量）。

1. 用百度账号登录 [百度网盘开放平台](https://pan.baidu.com/union/console)，完成开发者认证（个人即可），创建一个应用（类别选“软件”）。
2. 在 スス子文庫 的“设置 → 网盘”里填 AppKey 和 SecretKey。也可以在服务器上用环境变量 `BAIDU_APP_KEY`、`BAIDU_SECRET_KEY` 统一配置。
3. 点“连接百度网盘”，用百度网盘 App 扫码或在浏览器里授权。授权令牌只保存在你的服务器上，过期前会自动续期。
4. 点“导入 → 百度网盘”，勾选 EPUB、CBZ / ZIP，或者装着图片的文件夹：
   - 文件夹里直接是图片 → 当成一本漫画；
   - 文件夹里是一个个子文件夹或压缩包 → 每个算一卷，系列名用文件夹名。

网盘里的压缩包可以像普通书一样“下载到本机”离线看；图片文件夹只能在线看。从书架上删掉网盘里的书，不会删网盘里的文件。

### 设备直连（安卓 / Windows 客户端）

客户端会优先自己从百度下载，不经过服务器、不占服务器流量；网页版始终经服务器转发。

- 服务器带着令牌向百度请求一次下载地址，拿到百度跳转后的 CDN 地址（自带签名、会过期、不含令牌），只把这个地址发给客户端；地址里如果还带着令牌就拒绝直连。百度的 access_token / refresh_token 始终只在服务器上。
- 客户端用 Tauri 原生网络层（Rust reqwest）下载，带上百度要求的 `User-Agent: pan.baidu.com`，按 Range 分段读取，只跟随指向百度域名的跳转，并核对返回的 Content-Range。
- 直连失败（地址过期、百度按 IP 拒绝、网络错误、Range 对不上）会自动改走服务器转发，十分钟后再试直连。阅读器顶部会显示实际读取方式：设备直连百度网盘 / 经服务器转发 / 本机缓存。
- 直连地址只放在内存里，不写本地存储，不写服务器日志。
- “设置 → 网盘 → 检查设备直连”会随机跳到书里任意位置读 12 段，和服务器转发逐字节核对，并显示失败原因。服务器和设备在不同网络时，这就是跨 IP 下载的实测。

## 自动查资料和标签

- 编辑一本书 → “自动查资料”：先用书名去 Bangumi 和 AniList 找（公开接口，不用申请账号）；名字不标准（比如音译、俗称）找不到时，再调用一次 DeepSeek 搜索接口找出正式名称和别名，重新查一遍；最后由 AI 在候选里挑出最像的一部，你勾选要填哪些字段。
- 设置 → 自动查资料：填 DeepSeek 密钥（搜索接口按次计费，每千次 5 元）；“挑选结果用的模型”可以沿用 AI 助手的设置，也可以单独填一个便宜的模型（任何 OpenAI 兼容接口，比如 Liquid 的 LFM 模型），或者关掉只按名字相似度挑。Bangumi 令牌可选，只有查 R18 条目时才需要。
- 标签：编辑里添加标签。侧栏的“标签”默认收起，点旁边的小三角展开，点一个标签就是同标签的作品；搜索框输入 `#标签` 只搜这个标签。
- 系列：编辑里填了系列名的书就按系列显示，只有一本也可以。
- 搜索时书架改成宫格（可切列表），不再显示 3D 书架。

## 挂载：WebDAV、OPDS、SMB / NAS、各种网盘

书架右上角“导入”里可以挂载别处的书。文件留在原处，书架上只记位置，看的时候由你的服务器按需去取（不占服务器空间）。账号密码只存在服务器上。

- **WebDAV**：坚果云（密码用“第三方应用密码”）、Nextcloud、群晖 / 威联通 NAS、AList / OpenList 等。勾选 EPUB、CBZ / ZIP，或者整个装着图片的文件夹（当成一本漫画），放上书架。
- **OPDS**：Calibre、Calibre-Web、Komga、Kavita 等书库。可以一层层浏览、加载更多；“加入书架”会把书下载下来像本机文件一样导入。
- **SMB / NAS 共享、服务器上的文件夹**：浏览器和手机不能直接连 SMB，要先在服务器上把共享挂成目录（例如 `sudo mount -t cifs //NAS/共享 /mnt/nas -o username=…,password=…,iocharset=utf8`），再把这个目录写进环境变量 `MOUNT_ROOTS`（多个用冒号分隔），重启服务器后就能在“SMB / NAS”里选。没设置 `MOUNT_ROOTS` 时这一项不能用，避免把整个硬盘暴露出去。
- **阿里云盘、115、123 云盘、OneDrive、Dropbox、夸克网盘**：这些网盘没有给第三方阅读器的标准接口。推荐在服务器上装 [OpenList](https://github.com/OpenListTeam/OpenList)（AList 的社区版）并添加网盘，然后按 WebDAV 挂进来（默认地址 `http://服务器:5244/dav`）。百度网盘仍是直接连接。
- 已有的挂载在“设置 → 网盘与挂载”里管理：浏览、改密码、删除。

## 在线书库（Novelia）

侧栏“在线书库”接的是 [Novelia 轻小说机翻机器人](https://n.novelia.cc)：文库小说按封面宫格，网络小说按列表，可以搜索、按分级 / 连载状态筛选，滑到底自动加载下一页。点开一部作品能看到可下载的卷和各家翻译的进度，“加入书架”会让你的服务器去 Novelia 生成 EPUB、取回来，再按普通文件导入书架，并补上系列、卷号、标签、原名和简介。

- 必须连着自己的服务器才能用（Novelia 不允许网页直接跨站请求，所以由服务器转发）。
- 不登录也能浏览和下载大部分作品；在页面右上角可以登录 Novelia 账号，账号令牌只存在你的服务器上，不会下发到设备。
- 下载格式可选“中文”或“中日对照”，翻译按 Sakura → GPT → 有道 → 百度 的顺序取。没翻完的段落会以日文原文出现。
- 网络小说是整本下载；作者还在更新时，过一阵再加一次就是新的一份。
- 测试用的接口地址可以用环境变量 `NOVELIA_API`、`NOVELIA_AUTH` 改掉。

## 纸质书模式

阅读设置 → 操作：

- **翻页动画 → 仿真**：纸角跟着手指走，松手时翻过去或落回原位；点按、键盘、音量键翻页也是同样的翻纸动画，翻到下一章也会翻。双页时，翻起来那张纸的背面就是下一页，跟着折痕一起转。竖排暂时用滑动代替。
- **纸质书效果**：纸张纹理、双页中间的书缝阴影、两侧一页页叠起来的书边（左边是读过的、右边是没读的，厚度跟着进度变）。

## 漫画画质增强（waifu2x）

漫画阅读 → 设置 → 画质增强：用 waifu2x 给漫画降噪（3 级），后台排队先处理当前页和后面 10 页，处理好的页自动换上去，翻页时不用等。

- **高画质**：扫描漫画模型（swin_unet / art_scan），效果最好；**快速**：CUNet 模型，快一些。
- 计算在你自己的设备上做：有 WebGPU 的（新版 Chrome / Edge、Windows 版、较新的安卓）用显卡，几秒一页；没有的退回 CPU，会慢很多。
- 运行库（onnxruntime-web）和模型（来自 nagadomi/nunif，MIT 许可）第一次用到时由服务器下载到 `数据目录/waifu2x/`，之后各台设备都从你的服务器取。服务器下载不动时，可以设环境变量换镜像：`WAIFU2X_ORT_BASE`（默认 jsDelivr 上的 onnxruntime-web 1.20.1）、`WAIFU2X_MODEL_BASE`（默认 Hugging Face 上的 deepghs/waifu2x_onnx 20230504 版，例如换成 hf-mirror.com），或者手动把文件放进 `数据目录/waifu2x/ort/` 和 `数据目录/waifu2x/models/swin_unet/art_scan/noise3.onnx` 这样的位置。
- 处理结果只放在内存里，关掉书就释放；超过 1200 万像素的图会跳过。

## 同步是怎么工作的

- 服务器是唯一的数据源。导入一本书时，客户端在本地读出书名、作者和封面，再把文件上传；相同文件（按 SHA-256）不会重复保存。
- 打开一本没下载的书时，客户端只向服务器要正在读的那部分（每块 512KB），所以网速慢也能很快翻开；空闲时再在后台把整本补齐存到本机（可在设置里关掉）。
- 进度按“最后阅读的时间”为准：每次翻页先写本机，几秒后推到服务器；离线时攒着，联网后补传。打开一本书前会先拉一次最新进度。
- 合集、改名、删除需要联网才能操作。

## 关于云母效果

Windows 11 的客户端使用系统自带的云母（Mica）材质做窗口背景；Windows 10、安卓和网页版没有这个系统材质，用半透明毛玻璃模拟。

## 关于书脊上的文库标志

`app/img/labels/` 里的文库标志来自各文库官网和官方账号，只用于在自己的书架上区分文库；书脊排版是软件里的示意，不是逐版复刻的真实书脊。

漫画（CBZ / ZIP）用另一套单行本书脊：白底、封面色色带、品牌小标、彩色大卷号、“原作 / 作画”两列。`app/img/manga/` 收了 68 个漫画品牌的小标，大多是 2008 年前后的低清历史书脊小标，KADOKAWA 系另有官方品牌图；同一品牌有几个版本时可以在“编辑信息”里挑。JC、KC、GC、SC 这类好几个品牌共用的缩写不会自动套标志。

## 已知限制

- 文字不能选中复制，所以笔记是“记在某一页上”，不能划线高亮某一句；没有全文搜索。
- 竖排模式只能翻页，不能上下滚动，也没有双页。
- 只支持无 DRM 的 EPUB；不支持 PDF、MOBI、TXT、RAR/CBR。
- 单用户设计：一个密钥对应一个书架。
- 超过 4GB 的 ZIP64 压缩包不支持。
